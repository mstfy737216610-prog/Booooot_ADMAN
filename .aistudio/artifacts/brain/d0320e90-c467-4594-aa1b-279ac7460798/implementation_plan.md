# نظام سجل المنشورات الشامل، ذاكرة الأفكار التفاعلية، وقراءة الصور والربط التنافسي (Multi-Platform Academic Intelligence)

خطة معمارية تفصيلية لتطوير محرك البوت الأكاديمي ولوحة تحكم الويب، تشمل بناء سجل تدقيق شامل للمنشورات المقبولة والمرفوضة بأسبابها الدقيقة، لوحة أفكار تفاعلية (Interactive Idea Board) مع بطاقات حالة وملاحظات تشغيلية، تفعيل القراءة البصرية للصور والبوسترات الأكاديمية (Gemini Vision / Local OCR)، محرك التعلم التنافسي والربط المعرفي للجامعات، وتجهيز بنية النشر التلقائي المزدوج والمستقل لمنصة تويتر (X) وتيليجرام عبر واجهة الويب.

---

## مراجعة قرارات المستخدم والخيارات المؤكدة (User Review & Confirmed Decisions)

> [!IMPORTANT]
> تم تأكيد الخيارات المحورية التالية مع المستخدم خلال مرحلة الاستيضاح لتوجيه البناء المعماري:
> 
> 1. **قراءة وتحليل الصور والبوسترات الأكاديمية**:
>    - **القرار المؤكد**: استخدام حلول متوافقة ومجانية تعمل إما محلياً أو باستخدام المفاتيح المعتمدة بالموقع (`GEMINI_API_KEY` المتوفر مجاناً بنظام Multimodal Vision مع معالجة محلية للصور عبر مكتبات المعالجة).
>    - **حل المشكلة**: تنزيل الصورة من تيليجرام عبر `getFile` وقراءتها فورياً بالنموذج البصري لاستخراج نصوص الجداول والمواعيد والشروط بالكامل بدلاً من إهمال محتوى الصور.
> 
> 2. **ذاكرة الأفكار والتغذية الراجعة الذكية**:
>    - **القرار المؤكد**: لوحة أفكار تفاعلية (Interactive Idea Board with status tags and notes) تنظم الأفكار والملاحظات التشغيلية على شكل بطاقات كانبان مصنفة حسب الحالة (`جديدة`، `قيد الدراسة`، `معتمدة`، `منشورة`) مع إمكانية تحويل أي منشور مرفوض أو مقبول إلى فكرة مستقبلية بنقرة واحدة.
> 
> 3. **تكامل النشر على منصة تويتر (X)**:
>    - **القرار المؤكد**: نشر تلقائي مزدوج لتويتر وتيليجرام بنفس الآلية والواجهات، ولكن مع استقلالية تامة في صياغة منشورات تويتر (حد 280 حرف، وسوم مخصصة، صياغة مكثفة) عن منشورات تيليجرام المفصلة، مع إمكانية التفعيل والإيقاف المستقل من لوحة التحكم.

## 1. نظرة عامة والمفهوم الجوهري (Overview & Core Concept)

### ما يقدمه النظام (What It Delivers)
1. **سجل المنشورات الشامل والرقابة (Comprehensive Post Audit Log)**:
   - قسم المنشورات المنشورة: عرض وقت النشر، القناة المستهدفة، رابط المنشور، نص المنشور المحرر، والميديا المرفقة.
   - قسم المنشورات المرفوضة: عرض سبب الرفض الدقيق لكل خبر (تكرار خبر مماثل خلال 24 ساعة، إعلان تجاري غير مصرح، خبر غير أكاديمي أو خارج الشأن الطلابي، ضعف الأهمية) مع إمكانية مراجعة النص الأصلي ونقله لقائمة الأفكار.
2. **لوحة الأفكار والتغذية الراجعة الذكية (Idea Memory & Feedback Board)**:
   - واجهة بصرية مرنة تتيح للمشرف كتابة ملاحظات وتوجيهات تشغيلية ("عقد تعلم / خطوط فكرية") لتطوير المحتوى الطلابي.
   - إمكانية إضافة أفكار يدوية أو توليد أفكار تلقائية مستخلصة من هموم واستفسارات الطلاب في المجموعات ومصادر الجامعات.
3. **محرك قراءة الصور والبوسترات (Vision & Image Intelligence Engine)**:
   - حل جذري لمشكلة عدم قراءة الصور؛ حيث يقوم البوت عند استلام أي صورة أو ملصق أو ملف PDF بجلب الملف عبر `getFile`، وتحليله فورياً عبر الرؤية البصرية المجانية لاستخراج كافة التواريخ، شروط التسجيل، النسب، والروابط ونقلها لمحرك الصياغة.
4. **محرك الربط المعرفي والتفوق التنافسي (Competitive Learning Engine)**:
   - فحص دوري لحسابات الجامعات والمنافسين وتخزين أسلوبهم ونقاط ضعفهم في جدول `university_knowledge`.
   - توجيه المحرك الأكاديمي لإنتاج محتوى يتفوق على المنافسين بالتركيز على المشاكل العملية للطلاب (نسب الغياب، المكافآت، الحذف والإضافة، مواعيد البوابات).
5. **بنية النشر لمنصة تويتر (X Publishing Architecture)**:
   - واجهة مستقلة لإعداد مفاتيح وتوكنات تويتر وتفعيل النشر التلقائي، وتجهيز قوالب التغريدات وصياغتها بذكاء ضمن قيود تويتر دون التأثير على منشورات تيليجرام.

### الهوية البصرية (Visual Theme & Palette)
- **المظهر**: تصميم مكتبي حديث وعالي الكثافة (Enterprise SaaS Dashboard) متوافق مع معايير لوحات التحكم الإنتاجية وأدلة التصميم الخالية من الحشو.
- **توزيع الألوان (60-30-10)**:
  - 60% خلفية داكنة هادئة ورصينة (`#0B0F17` / `#0F172A`).
  - 30% أسطح كروت وألواح رقيقة مع حواف دقيقة 1px (`border-slate-800` / `bg-slate-900/60`).
  - 10% ألوان حالة وظيفية مركزة: زمردي (`#10B981`) للمنشورات الناجحة، كهرماني (`#F59E0B`) للأفكار قيد الدراسة، وياقوتي (`#EF4444`) للمنشورات المرفوضة، وسماوي (`#0EA5E9`) لإجراءات تويتر ونظام الرؤية البصرية.
- **الطباعة**: أرقام جدولية ثابتة (`tabular-nums font-mono`) للأوقات والتواريخ والإحصائيات، وخط عربي واضح ومتناسق للنصوص الأكاديمية والبطاقات.

## 3. القرارات المعمارية والمفاضلات التقنية (Key Decisions & Trade-Offs)

1. **قراءة وتحليل الصور (Vision Architecture)**:
   - **الخيار المعتمد**: محرك هجين يدمج استدعاء `tg_bot.get_file(file_id)` لتنزيل الصورة فور استلامها، وتمريرها مباشرة كـ Multimodal Inline Data إلى النموذج البصري المتاح مجاناً `gemini-3.8-flash` مع معالجة محلية للنصوص والبيانات.
   - **السبب**: نماذج الـ Vision الحديثة تتفوق بمراحل هائلة على محركات الـ OCR الكلاسيكية في قراءة الجداول العربية المعقدة والخطوط المزخرفة والبوسترات الملونة دون أي تكلفة إضافية.

2. **سجل التدقيق المنفصل للمنشورات المرفوضة والمقبولة**:
   - **الخيار المعتمد**: جدول دائم `post_audit_log` في SQLite يحفظ بدقة: `post_type` (`published` / `rejected`)، `rejection_reason`، `source_platform`، `university_id`، `raw_content`، `published_content`، `target_channel`، و `media_url`.
   - **السبب**: منع فقدان أي خبر، وتوفير شفافية مطلقة للمشرف لمعرفة سبب رفض أي منشور واسترجاعه بضغطة زر.

3. **لوحة الأفكار التفاعلية كعقد معرفية (Idea Board & Knowledge Nodes)**:
   - **الخيار المعتمد**: جدول `future_ideas` مربوط بـ `university_knowledge`، بحيث تحتوي كل فكرة على `operational_notes` (التوجيهات والدروس المستفادة) و `status` و `tags` و `competitor_comparison`.
   - **السبب**: تحويل الملاحظات إلى "ذاكرة حية" يتم حقنها تلقائياً في موجه الذكاء الاصطناعي أثناء صياغة المنشورات القادمة.

4. **معمارية نشر تويتر المستقلة**:
   - **الخيار المعتمد**: إضافة محرك صياغة مخصص لتويتر (`format_for_twitter`) يراعي قيد الـ 280 حرف، صياغة الخطاف الصحفي (Hook)، وانتقاء الهاشتاجات الأكثر فاعلية، مع بناء واجهة إعدادات متكاملة لاستقبال بيانات الربط ومفاتيح API أو جلسات النشر فور تزويدها.

## 4. المخطط التقني واستراتيجية البيانات (Technical Architecture & Data Strategy)

### مخطط تدفق البيانات والمعالجة (Data Flow Architecture)

```
[ Telegram / Twitter / RSS / Direct Photo ]
                   │
                   ▼
       [ 🖼️ Vision & Media Handler ]
    (تنزيل الصورة وقراءة الجداول والنصوص)
                   │
                   ▼
       [ 🛡️ Filter & Quality Gate ]
  ┌────────────────┴────────────────┐
  │                                 │
[ المقبول: صياغة وتنافسية ]       [ المرفوض: رصد السبب الدقيق ]
  │                                 │
  ├─► [ تيليجرام: صياغة مطولة ]     ├─► حفظ في post_audit_log (مرفوض)
  ├─► [ تويتر: صياغة 280 حرف ]      └─► [ زر: تحويل إلى فكرة مستقبلية ]
  │                                                 │
  ▼                                                 ▼
[ قنوات النشر ]                       [ 💡 لوحة الأفكار وعقد التعلم ]
                                                    │
                                                    ▼
                                    [ 🧠 تحديث هوية الجامعة والذاكرة ]
```

### مخطط جداول قاعدة البيانات (Database Schema Updates)

1. **جدول سجل التدقيق الشامل `post_audit_log`**:
   - `id`: INTEGER PRIMARY KEY AUTOINCREMENT
   - `post_id`: TEXT
   - `status`: TEXT ('published', 'rejected', 'pending')
   - `title`: TEXT
   - `raw_content`: TEXT
   - `final_content`: TEXT
   - `rejection_reason`: TEXT (مثل: `تكرار خبر مماثل`, `إعلان تجاري`, `محتوى غير أكاديمي`, `ضعف الأهمية الطلابية`)
   - `source_type`: TEXT ('telegram', 'twitter', 'rss', 'manual_image')
   - `source_origin`: TEXT
   - `target_destination`: TEXT
   - `target_univ`: TEXT
   - `media_type`: TEXT ('photo', 'video', 'document', 'text')
   - `media_url`: TEXT
   - `created_at`: TEXT
   - `published_at`: TEXT

2. **جدول ذاكرة الأفكار والتغذية الراجعة `future_ideas`**:
   - `id`: INTEGER PRIMARY KEY AUTOINCREMENT
   - `title`: TEXT NOT NULL
   - `description`: TEXT
   - `operational_notes`: TEXT (التوجيهات والملاحظات الإشرافية / عقدة الفكرة)
   - `status`: TEXT DEFAULT 'new' ('new', 'in_progress', 'ready', 'published', 'archived')
   - `priority`: TEXT DEFAULT 'medium' ('low', 'medium', 'high')
   - `tags`: TEXT DEFAULT '[]'
   - `university_id`: TEXT
   - `source_post_id`: INTEGER (رابط المنشور المقبول أو المرفوض الأصلي)
   - `twitter_ready`: INTEGER DEFAULT 0
   - `telegram_ready`: INTEGER DEFAULT 0
   - `created_at`: TEXT
   - `updated_at`: TEXT

3. **جدول إعدادات النشر على تويتر `twitter_publishing_settings`**:
   - `key`: TEXT PRIMARY KEY
   - `enabled`: INTEGER DEFAULT 0
   - `api_key`: TEXT
   - `api_secret`: TEXT
   - `access_token`: TEXT
   - `access_secret`: TEXT
   - `bearer_token`: TEXT
   - `auto_thread`: INTEGER DEFAULT 0
   - `max_chars`: INTEGER DEFAULT 280
   - `custom_hashtags`: TEXT
   - `updated_at`: TEXT

## 5. خطة التنفيذ خطوة بخطوة (Step-by-Step Implementation Steps)

1. **المرحلة 1: قاعدة البيانات ومحرك السجلات والأفكار (Database Layer)**
   - إنشاء جداول `post_audit_log`، `future_ideas`، و `twitter_publishing_settings` في `database.py`.
   - توفير دوال الاستعلام والفلترة والإضافة والتحديث، ودالة تحويل المنشور المرفوض/المقبول إلى فكرة مستقبلية.

2. **المرحلة 2: حل مشكلة قراءة الصور في البوت (Vision Engine in main.py)**
   - بناء دالة `extract_text_and_schedule_from_image` في `main.py` باستخدام `getFile` والتكامل المباشر مع الرؤية البصرية المجانية لاستخراج الجداول والتواريخ.
   - حقن النص المستخرج من الصورة مباشرة في مصفوفة الصياغة الذكية ليعامل كخبر كامل متكامل.

3. **المرحلة 3: تحديث مسار الفلترة وتسجيل المنشورات المقبولة والمرفوضة**
   - تسجيل كل خبر يتم قبوله ونشره تلقائياً في `post_audit_log` كـ `published`.
   - تسجيل كل خبر يتم استبعاده في `post_audit_log` كـ `rejected` مع توثيق سبب الرفض الدقيق وتفاصيله.

4. **المرحلة 4: خادم التطبيق وتوفير نقاط الـ API (server.ts Backend)**
   - إضافة مسارات API لسجل التدقيق: `GET /api/audit-logs` (مع الفلترة والبحث)، `POST /api/audit-logs/convert-to-idea`.
   - إضافة مسارات API للوحة الأفكار: `GET /api/ideas`، `POST /api/ideas`، `PUT /api/ideas/:id`، `DELETE /api/ideas/:id`، `POST /api/ideas/:id/publish`.
   - إضافة مسارات API لإعدادات وتجهيز تويتر: `GET /api/twitter/config`، `POST /api/twitter/config`، `POST /api/twitter/test-tweet`.

5. **المرحلة 5: تطوير واجهة الويب (React Dashboard Upgrade)**
   - إنشاء مكون `PostAuditLogPanel.tsx` لإدارة سجل المنشورات المقبولة والمرفوضة والبحث فيها.
   - إنشاء مكون `InteractiveIdeaBoard.tsx` كلوحة كانبان تفاعلية لإدارة الأفكار والملاحظات وعقد التعلم.
   - إنشاء مكون `TwitterIntegrationPanel.tsx` لإدارة النشر على تويتر والتحكم بالإعدادات والصياغة المنفصلة.
   - دمج المكونات الجديدة بسلاسة في شريط الملاحة الرئيسي في `App.tsx` و `Header.tsx`.

6. **المرحلة 6: التحقق والاختبار الشامل**
   - فحص الأخطاء عبر `lint_applet` و `compile_applet`.
   - التحقق من تشغيل السيرفر والبوت وسلامة قراءة الصور وتخزين الأفكار وسجلات المنشورات.
